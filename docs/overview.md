# Огляд проєкту Referendum

Це соціальна платформа для проведення онлайн-опитувань і референдумів. Проєкт побудований на шаблоні **Yii 2 Advanced**, що забезпечує поділ на фронтенд, бекенд та спільні компоненти.

## Основні можливості

- створення та редагування опитувань;
- голосування за варіанти відповідей;
- голосування відбувається лише через POST-запити, тому вибраний варіант не фігурує в URL;
- перегляд результатів без голосування через стилізовану кнопку «Побачити результати», яка не додає параметрів у URL;
- коментування та оцінка коментарів;
- побудова графіків результатів;
- поширення опитувань у соцмережах та копіювання прямого посилання.
- фільтрація опитувань за період (день, тиждень, півроку, рік; за замовчуванням — останні півроку).
- оновлено переклад періоду «півроку» для норвезької локалі.

## Структура

- **frontend/** – публічна частина сайту з модулями `poll`, `user` та `ajax`;
- **backend/** – адміністративна панель;
- **common/** – спільні моделі та налаштування.

## Розробницьке середовище

Для швидкого старту використовується `docker-compose`:

```bash
docker-compose up -d
```

Після запуску фронтенд доступний на [http://localhost:20080](http://localhost:20080), а бекенд – на [http://localhost:21080](http://localhost:21080).

## Встановлення без Docker

```bash
composer install
php init
cp .env.example .env
```

Після копіювання файлу `.env` заповніть у ньому змінні `DB_DSN`, `DB_USERNAME`, `DB_PASSWORD` та за потреби `DB_TEST_DSN`.

## Версія PHP

Сайт наразі працює на версії **PHP 7.3**. Рекомендується поступово перейти на новішу гілку PHP (наприклад, 8.2 або 8.4) для покращення продуктивності та безпеки. Перед оновленням варто протестувати сумісність усього коду.

## Канонічні піддомени

Сторінки опитувань автоматично перенаправляються на піддомен, що відповідає мові опитування. Наприклад, звернення до
`https://ua.referendum.social/poll/573` або `https://referendum.social/poll/573` буде переадресовано на
`https://en.referendum.social/poll/573`, якщо опитування створене англійською. Для коректної індексації додається тег
`<link rel="canonical">` з посиланням на канонічну адресу.

Головна сторінка та списки тегів отримують канонічні посилання, що повторюють поточний домен і шлях сторінки.
Основний домен `https://referendum.social/` залишається активним без редіректу на англомовний піддомен, а тег
`<link rel="canonical">` завжди вказує на фактичну адресу (включно з пагінацією на кшталт `https://referendum.social/page/2`).
Завдяки цьому пошукові системи бачать коректну структуру без дубльованих URL.

Статичні сторінки (наприклад, `/updates`) тепер генерують канонічне посилання, що відповідає мовному піддомену сторінки. Це уникає дублювання між піддоменами й чітко підказує пошуковикам, яку адресу індексувати.

Пагінація на головній тепер не додає параметр `?page=1` для першої сторінки. Кнопка повернення з другої сторінки тепер веде на
`https://<locale>.referendum.social/` без дублювання основної адреси, що спрощує індексацію та запобігає появі дубльованих
сторінок у пошукових системах.

## Доступ до robots.txt

- У кореневому `.htaccess` додано окреме правило, яке дозволяє віддавати `robots.txt` без примусового редіректу на HTTPS.
- Для кожного піддомену (`en`, `ru`, `ua`, `no`, `nz`) та основного домену використовується власна версія файлу з посиланням на відповідний `sitemap.xml`.
- Піддомен `nz` віддає `robots.txt`, синхронізований із рештою мовних піддоменів, і публікує `Sitemap: https://nz.referendum.social/sitemap.xml`.
- Правила в `robots.txt` для мовних піддоменів уніфіковані: перелік `Disallow` повторюється без змін, блок `Allow` залишається порожнім, а URL карти сайту містять домен чи піддомен, для якого віддається файл.
- З кореневого застосунку прибрано дубльований `frontend/web/robots.txt`, щоб зовнішній вебсервер віддавав лише актуальні файли для кожного домену.
- Завдяки цьому файл доступний одночасно за `http://` та `https://`, що спрощує перевірку сайту пошуковими роботами.
- Після вибору потрібного файлу застосовується прапор `[END]`, щоб Apache завершував обробку і не передавав запит далі до frontend-додатку.

## Мета-теги профілів

Всі публічні сторінки профілів користувачів (`/Profile/<id>`) та їхні сторінки пагінації тепер віддають мета-тег
`<meta name="robots" content="index, follow">`. Це дозволяє пошуковим системам індексувати профілі та переходити за посиланнями
всередині них. Налаштування виконується на рівні контролера, тож мета-тег додається для будь-якої сторінки профілю незалежно від
параметра `page`. Канонічне посилання тимчасово веде на головну сторінку відповідного піддомену (`https://<locale>.referendum.social/`),
щоб уникнути дублювання під час подальших змін маршрутизації. Тайтл лишається у форматі «{нікнейм} - Referendum»,
а опис – «Polls and opinion about everything - take part in polls and discussion: vote, write comments, suggest vote options or create your own polls. 📊 Dive in! 🌟».

## Мікророзмітка та часові пояси

Дата публікації опитувань у мікророзмітці `DiscussionForumPosting` тепер містить часовий пояс **America/New_York**. Часовий пояс задається в атрибуті `content` і не відображається користувачам на сторінці.
Дата публікації коментарів переноситься у окремий тег `<meta itemprop="datePublished">` всередині кожного блоку коментаря; видимий текст дати лишається без змін.
Мета‑теги `mainEntityOfPage` та `url` отримують абсолютну адресу сторінки через `Yii::$app->request->absoluteUrl`, що гарантує коректні посилання незалежно від домену.
У `<head>` сторінки додається мета‑тег `og:image`, що генерується на основі `Yii::$app->request->hostInfo` і вказує на файл `/img/kvadrat.png` поточного піддомену.

Профілі користувачів на сторінці `/Profile/<id>` отримали мікророзмітку `ProfilePage` з головною сутністю `Person`. У структуровані дані входять ПІБ, нікнейм, електронна пошта (якщо користувач зробив її публічною), короткий опис з профілю, абсолютна адреса сторінки, окремі лічильники для кількості опитувань і коментарів, а також рейтинг користувача у форматі `LikeAction`. Для уникнення помилкових посилань ми не передаємо зображення, адже профілі наразі не мають власних аватарів. Це допомагає пошуковикам краще розуміти зміст профілю і показувати розширені результати у видачі.

- Лічильники профілю («Рейтинг користувача», «Всього опитувань», «Всього коментарів») тепер перекладені англійською, російською та норвезькою мовами, тож інтерфейс сторінок `/Profile/<id>` залишиться повністю локалізованим для всіх наявних піддоменів.

## Генерація Sitemap

Для побудови XML‑карт сайту використовується консольна команда:

```bash
php yii sitemap/index
```

До sitemap додаються всі існуючі опитування незалежно від статусу. Після видалення опитування через адмінку воно автоматично припиняє потрапляти до карти сайту.

Для кожної URL‑адреси вказується тег `lastmod`, що відображає дату останнього оновлення відповідного опитування або тегу. Значення записується лише у форматі `YYYY-MM-DD` без часу. Якщо для конкретної сторінки немає достовірної дати, тег `lastmod` взагалі не додається, аби уникнути порожніх значень. При визначенні цієї дати враховуються редагування самого опитування, додавання коментарів чи голосів та зміни пов'язаних тегів.

> **Примітка.** Починаючи з останнього оновлення, файли `sitemap.xml` та їхні індекси записуються атомарно у тимчасовий файл із перевіркою на порожній вміст. Це виключає появу порожніх карт сайту у випадку збоїв під час генерації.

## Текстовий опис тегів

На сторінках тегів відображається автоматично сформований блок із короткою статистикою: дата створення тегу, кількість пов'язаних опитувань, найпопулярніше опитування (за кількістю голосів), опитування з найбільшим рейтингом та дата останнього опитування. Назви опитувань містять посилання на відповідні сторінки.

Опис показується лише на першій сторінці списку тегу; на сторінках пагінації цей блок приховано.

В англомовній локалізації для кращої індексації використовуються ключові фрази на кшталт "Opinions {tag} polling" та "polls {tag} update".

Для російської та норвезької версій додано оновлені переклади цього опису, а формат дат автоматично підлаштовується під вибрану мову.

Опис англійською також очищено від залишків українського тексту, тож усі локалі відображають повні переклади без змішування мов.

Списки опитувань усередині тегів тепер відсортовані за датою додавання у спадаючому порядку, тож на початку сторінки одразу видно найновіші публікації.

## Тайтл і опис сторінок тегів

Сторінки тегів отримали оновлені метатеги:

- заголовок формату «Останні опитування {tag} та думка громадськості | Referendum»;
- опис з кількістю опитувань: «Опитування та думки щодо {tag}: беріть участь у {count} захопливих опитуваннях, висловлюйте свої думки, коментуйте актуальні питання, спілкуйтеся з іншими та досліджуйте результати.»
- попередня генерація метатегів у `PollSearch` видалена, тож конфліктів більше немає.

## Виправлення JavaScript

Скрипти сторінки опитування тепер використовують повне ім'я `jQuery` замість скорочення `$`. Це усуває помилку `Uncaught ReferenceError: $ is not defined`, що з'являлась у браузері під час роботи з формою додавання відповіді та фільтрами.


Код JavaScript реєструється через `View::registerJs`, тому виконується лише після завантаження бібліотеки jQuery. Завдяки цьому усувається помилка `ReferenceError: jQuery is not defined`.

Кнопка поширення з копіюванням посилання використовує API `navigator.clipboard` і працює у сучасних браузерах без додаткових резервних методів.

## Фільтрація голосів

На сторінці опитування реалізовано показ вибірки голосів за статтю, віком, країною та статусом реєстрації користувачів. Фільтр «Регіон» тимчасово вимкнено, але лишається закоментованим у коді для можливого відновлення.
Під час вибору фільтрів результати графіка перераховуються на основі реальних голосів користувачів, що відповідають
заданим параметрам. Гостьові голоси не враховуються при застосуванні фільтрів, окрім випадку вибору лише незареєстрованих.

Після останнього оновлення виправлено врахування гостьових голосів: фільтри за статтю, віком та країною знову працюють коректно разом із фільтром реєстрації.

Додатково запит до таблиці `option_vote` відкидає записи з порожнім `user_id`, тож гостьові голоси не змішуються із зареєстрованими. Гостьові голоси враховуються лише тоді, коли не задано жодного іншого фільтра.

Додатково виправлено підрахунок загальної кількості голосів, тож відсотки відповідають реальним даним, а фільтр «Реєстрація» працює одночасно з іншими параметрами.

### Оптимізація виджета списку опитувань

- Виджет `frontend/widgets/WPollList.php` тепер самостійно встановлює дефолтні значення для мови, категорії, тегу, ліміту, сортування та періоду. Це зменшило обсяг коду і спростило додавання нових параметрів.
- Щоб уникнути зайвих запитів до сервісу користувачів, інформація про поточного користувача визначається лише за потреби.
- Блок відладки `{debug}` тепер вимкнений за замовчуванням і активується лише тоді, коли виджету явно передають властивість `showDebug = true`. Це запобігає появі службового блоку на публічних сторінках, але зберігає можливість детального аналізу під час ручного тестування в середовищі `YII_DEBUG`.
- Для уникнення дубльованого блоку мікророзмітки профілю на головній, в пошуку та на сторінках тегів виджет більше не підставляє авторизованого користувача автоматично. Тепер дані профілю зʼявляються лише тоді, коли їх явно передає відповідний контролер (наприклад, на сторінці `/Profile/<id>`).
- Шаблон сортування використовує лише мінімальний набір даних, що пришвидшує відмальовування пагінації на сторінках із великою кількістю опитувань.

## Усунення залишків Yii 1

У шаблоні перегляду опитування (`frontend/views/poll/view.php`) видалено застарілі виклики `Yii::app()`. Тепер використовується синтаксис `Yii::$app` та помічник `Url::to()`, що відповідає стандартам Yii 2.



## Стилі

Більшість таблиць стилів підключаються з атрибутом `rel="preload"` і після завантаження перетворюються на звичайні `stylesheet`. Це зменшує час відображення. Щоб уникнути дивних HTML‑послідовностей на кшталт `&#039;` у атрибуті `onload`, цільове значення `rel` зберігається в `data-rel`, а перемикання виконується через `this.rel = this.dataset.rel`. Водночас критичний файл `bootstrap.min.css` завантажується стандартно через `rel="stylesheet"`, щоб уникнути зміщення макета (CLS). Для користувачів без увімкненого JavaScript у шаблоні є блок `<noscript>`, який підключає всі стилі звичайним способом.

### Перевірка preload + noscript

- У `frontend/assets/AppAsset.php` додано пояснювальний коментар до preload-опцій, а в шаблоні `frontend/views/layouts/main.php` fallback-посилання тепер явно задають `rel="stylesheet"`.
- Скрипти `frontend/web/js/custom.js` та `frontend/web/js/custom-modal.js` виконуються всередині `try/catch`, тому збої бізнес-логіки не впливають на інлайн-обробник `onload`, який перемикає preload на stylesheet.
- Логіка копіювання посилань отримала запасний шлях через `document.execCommand`, тож помилки Clipboard API більше не зупиняють виконання коду.
- Глобальні об'єкти (наприклад, `window.Share` та `window.highchartColors`) оголошено явно, що спрощує налагодження у headless-браузерах і гарантує однакову поведінку для користувачів і Googlebot.

### Слайдер топових опитувань

- Верхні картки опитувань залишають у фокусі лише назву як клікабельний елемент, але інформаційний шар з рейтингом більше не перекриває лінк. Завдяки оновленим стилям `.inner_slide_b` посилання доступне як на ховері, так і під час клавіатурної навігації.
- Перехід між станами супроводжується плавною зміною непрозорості, тому макет не «стрибатиме», а взаємодія залишається інтуїтивною.

- Слайдер топових опитувань у хедері оновлено так, щоб клікабельною лишалась лише назва опитування, а не весь блок. CSS збережено таким, що не змінює зовнішній вигляд елементів, тож поведінка слайдера лишається звичною для користувачів.

Блок `.item_normal` у футері тепер використовує flexbox, завдяки чому текст центрується по горизонталі й вертикалі, а висота контейнера автоматично підлаштовується під довжину вмісту.

Список останніх і популярних опитувань у сайдбарі перероблено так, що посилання тепер містить лише назву опитування, а блок зі статистикою голосів розташовано поза тегом `<a>`. Додані стилі зберігають попередній вигляд і відступи елемента.

Додатково праворуч від показника голосів у цьому блоці відображається кількість коментарів з окремою піктограмою. Макет використовує flexbox, тож на вузьких екранах рядки акуратно переносяться без порушення вирівнювання.

## Повідомлення про застарілий браузер

Спливаючий банер із текстом «Your browser is out-of-date» повністю прибрано з публічного шаблону. Інтерфейс більше не блокує перегляд контенту користувачам сучасних браузерів без нав'язливих нагадувань про оновлення.

- З головного asset-бандла вилучено стиль `outdatedBrowser.min.css`, щоби сайт не тягнув зайві файли для відсутнього банера.
- У `main.js` прибрано виклик `detectOutdatedBrowser()`, який раніше запускав плагін без перевірки фактичної застарілості браузера.


## Валідація HTML

- Атрибути `width` та `height` у логотипі хедера вказані без `px`, що відповідає стандарту HTML і проходить валідацію.

## Голосування без GET-параметрів

- Усі кнопки голосування відтепер є формами з методом POST та прихованим полем `option`.
- Контролер `PollController::actionVote()` відхиляє запити, що не є POST, та повертає користувача до сторінки опитування.
- Віджет `poll-list` додає стандартний CSRF-токен, тому голоси зі списків не блокуються захистом від підробки запитів.
- Макети та демо-шаблони містять коментарі з інструкцією додати CSRF-токен при реальному рендері.
