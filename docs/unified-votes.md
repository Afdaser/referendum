# Спільна вибірка голосів

Усі нові та перенесені голоси зберігаються в одній фізичній таблиці `poll_vote`.
`is_guest = 1` позначає гостьовий голос, `is_guest = 0` — голос зареєстрованого користувача.
Для зареєстрованих голосів стать, вік, країна та регіон читаються з **поточного профілю**.
Копії демографічних даних профілю на момент голосування не створюються. Зміна профілю змінює відповідні вибірки старих голосів.
Гість доповнює свій голос добровільно; пропущені дані залишаються невідомими.

Країни й регіони мають спільні ID у `country` і `country_region`. Коди `country.iso_code`
та `country_region.code` дозволяють зіставити гостьовий вибір штату з існуючим регіоном
профілю, не покладаючись на його переклад під час голосування. Інші країни використовують
наявні ID того самого довідника; їхні окремі форми збору локацій ця зміна не вмикає.
Фінальне питання про штат доступне лише на `en.referendum.social`.

Фільтри країни, регіону, статі, віку й реєстрації поєднуються та однаково застосовуються
до стовпчикової, кругової й лінійної діаграм. Показник «Голосів у вибірці» — кількість
голосів після застосування всіх фільтрів. Наприклад, 45 гостьових і 20 зареєстрованих
голосів із Каліфорнії дають 65; фільтр реєстрації дозволяє побачити 45 або 20 окремо.
Невідома локація не потрапляє до вибірки конкретної країни/регіону.

## Розгортання поверх уже застосованого PR

**Не відкочуйте `m261026_000001_add_location_to_guest_vote` і не видаляйте її колонки.**
Нова міграція `m261102_000001_unify_poll_votes` читає та переносить ці дані.

1. Зробіть резервну копію бази та перевірте її відновлення.
2. Увімкніть режим обслуговування; зупиніть усі web/queue/cron-процеси, які записують голоси,
   профілі або довідники. Це не міграція для rolling deployment: старий і новий код не повинні
   записувати голоси одночасно. MySQL DDL не є транзакційним.
3. Розгорніть новий код і виконайте `php yii migrate --interactive=0`.
4. Якщо ввімкнено кеш схеми, очистіть його: `php yii cache/flush-schema db --interactive=0`.
   Перезапустіть довгоживучі процеси застосунку.
5. Перевірте загальні та роздільні лічильники, фільтри країни/регіону, новий гостьовий та
   зареєстрований голос, пропуск локації. Лише після успішної перевірки відновіть доступ.

Міграція:

- Перевіряє довідник США перед зміною схеми. Використовує існуючі ID штатів за англійськими,
  українськими та російськими назвами або поштовими кодами; відсутні штати додає.
- Якщо є кілька записів США, неоднозначні штати або використані в профілях регіони США,
  які неможливо зіставити, зупиняється **до зміни схеми** з повідомленням/ID.
  Перевірте ці записи: виправте назву до відповідного штату або явно доповніть зіставлення
  в міграції. Не видаляйте регіони профілів навмання. Території США поза списком 50 штатів і DC
  також потребують явного рішення, якщо вони вже використовуються у профілях.
- Копіює всі голоси та перевіряє кількість для кожного типу перед перемиканням таблиць.
  Історичні дублікати не видаляє; унікальні ключі не допускають нових повторних голосів
  одного акаунта або одного гостьового IP в межах опитування.
- Не приписує США голосам без вибраного штату. Старі коди зберігаються для аудиту,
  але фільтрація гостьової локації використовує `country_id`/`region_id`.
- Зберігає старі таблиці як `option_vote_archive` і `option_guest_vote_archive`.
  Вони більше не беруть участі в підрахунках і не отримують нових голосів.
- Створює під старими назвами `option_vote` і `option_guest_vote` SQL-представлення
  двох типів голосів над `poll_vote`. Це не дві копії даних: вони забезпечують сумісність
  старих лічильників, статистики тегів, адмінки й зв'язків моделей.
- Гостьові ID перенумеровує для уникнення колізій із зареєстрованими. Поле `legacy_guest_id`
  зберігає відповідність. Незавершені гостьові сесії переводяться на нові ID з перевіркою IP.

## Якщо міграція зупинилася

Не відновлюйте запис голосів і не запускайте міграцію повторно навмання.
Помилки перевірки довідника до DDL можна виправити й повторити запуск.
Якщо вже з'явилися `poll_vote`, нові колонки довідника або архіви, це частково виконане
перетворення: перевірте журнал і стан схеми. Найпростіше відновити резервну копію,
усунути причину та повторити міграцію, поки всі writers залишаються зупиненими.

`migrate/down` навмисно відмовляється відкочувати це перенесення: після появи нових голосів
повернення до архівів втратило б їх. Відновлювати резервну копію без додаткового перенесення
нових голосів можна лише до повторного відкриття сайту для запису.

Архіви можна прибрати окремо після перевірки та завершення періоду зберігання резервної копії:

```sql
-- Виконуйте лише після перевірки; врахуйте префікс таблиць, якщо він налаштований.
DROP TABLE option_guest_vote_archive, option_vote_archive;
```

Не видаляйте SQL-представлення `option_vote` та `option_guest_vote`: їх використовує застосунок.
